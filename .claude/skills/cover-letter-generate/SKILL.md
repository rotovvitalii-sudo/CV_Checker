# Письмо без надиктовки

Второй путь к письму (первый — `cover-letter` из надиктовки). Кандидат не говорит текст — ты пишешь
сам, но так, чтобы читатель услышал его, и так, чтобы каждый факт можно было проверить.

## Жёсткие правила

1. **Факты только из базы.** Любая цифра, срок, компания, продукт, роль, результат — только из
   `output/<…>/CV.md` или `knowledge-base/cards/` (и `knowledge-base/master-cv.md`). Пометки `NDA` /
   `не использовать` / `предположение` — не трогать. Нет в базе — нет в письме, даже если «очевидно».
2. **Трассировка обязательна.** Каждое предложение письма — в `04-generated-trace.json` с тегом:
   `fact` (есть факт о кандидате; `sources` — файлы, где он написан) или `link` (обращение, связка,
   мотивация, интерес к компании, закрытие — без фактов о его опыте). Название компании из его опыта
   и любое число в `link` — нельзя; исключение — числа из текста вакансии (K-12, «24/7»). «First 90 days»
   пиши словами («first three months»), если 90 нет в вакансии.
3. **Голос — его.** Если есть `knowledge-base/voice.md` (голосовой профиль, скил `voice-profile`) — читай
   только его: там уже выписаны манера, обороты и запреты, надиктовки ради голоса не читай (дешевле и быстрее).
   Профиля нет — прочитай надиктовки писем `knowledge-base/raw/*letter*.md` и 3–5
   надиктовок кейсов, которые использует письмо. Возьми манеру: как он заходит в тему, порядок мысли
   (контекст → что сделал сам → результат), короткие прямые фразы, его характерные обороты в близком
   переводе («я это продавил» → "I pushed this through"). Целыми кусками надиктовки не копировать.
4. **Формат и запреты — как в `cover-letter`** (`.claude/skills/cover-letter/SKILL.md`, правила 3, 6, 7):
   первое лицо, разговорный, но грамотный английский; по умолчанию 180–280 слов, 3–4 абзаца, без
   заголовка; формат может задать вакансия; не пересказывать CV; «I am excited to apply» и подобное — нет.
5. **Humanizer обязателен** (`.claude/skills/humanizer/SKILL.md`): `scorer/check_humanize.py` → `score ≤ 3`.
6. **Пробелы не замазывать.** Требования вакансии, которых нет в базе, в письме не обещать. Если
   главный пробел критичен — можно одной честной фразой (`link`, без выдуманных фактов).

## Процесс

### Шаг 0. Входы
- Вакансия `vacancies/<…>.md`; CV `output/<…>/CV.md`; `02-match-report.md`, `report.md` (риски).
- Структура `output/<…>/04-letter-outline.json`. **Нет файла** — сначала выполни скил `letter-outline`
  (`.claude/skills/letter-outline/SKILL.md`) и проверь его `scorer/check_outline.py`.
- Карточки — по фактам структуры и `knowledge-base/cards/INDEX.md`.
- Голос — правило 3.

### Шаг 1. Черновик по структуре
Блоки структуры — абзацы письма (порядок можно сжать: 4–5 блоков → 3–4 абзаца). Факты — из `facts`
структуры и карточек; подсказки структуры — это задачи абзацев, а не текст.

### Шаг 2. Трассировка → `output/<…>/04-generated-trace.json`
```json
{"sentences": [
  {"text": "Hi Brightclass team,", "tag": "link"},
  {"text": "At Northwind Learning I moved us from cohort launches to a subscription, and it grew to 15K+ paid users.",
   "tag": "fact", "sources": ["knowledge-base/cards/northwind-subscription-model.md"]}
]}
```
Предложения — ровно в порядке письма, вместе с обращением и подписью. Строка `Subject:` в трассировку не входит.

### Шаг 3. Humanizer
Собери `output/<…>/Cover Letter.md` из предложений трассировки (абзацы — пустой строкой; если вакансия
принимает заявки по email — первой строкой `Subject: …`). Прогони:
```bash
.venv/bin/python scorer/check_humanize.py --file "output/<…>/Cover Letter.md"
```
Чини до `PASS`. **После каждой правки обнови трассировку**, чтобы она совпадала с письмом слово в слово.

### Шаг 4. Проверка фактов
```bash
.venv/bin/python scorer/check_generated.py --name "<Роль - Компания>"
```
`pass: false` → исправь (источник, тег, расхождение с письмом, длина) и проверь снова.

### Шаг 5. Итог
`output/<…>/letter-summary.json`:
```json
{"mode": "generated", "questions": [], "removed": [],
 "facts_from": ["карточки, которые использованы"], "cards_used": ["<id карточки>"],
 "card_suggestions": [{"fact": "…", "quote": "…", "card": "<id или null>", "source": "<файл надиктовки>"}],
 "note": "одна фраза по-русски"}
```
`card_suggestions` — факты, которые ты увидел в надиктовках (`knowledge-base/raw/`), но не взял, потому что их нет
в карточках и CV (например, «пришёл вторым человеком»). Кандидат подтвердит их на экране «База кейсов»; не дублируй
их в `questions`.
`questions` — что стоит проверить глазами (спорные формулировки, тон). В чат — коротко по-русски:
слова, факты N/N с источником, humanizer-score, на какие кейсы опирается письмо.

## Инсайты кандидата (C12)
Можно не больше одной фразы точки зрения кандидата из инсайта (блок в промпте) — в части «почему эта компания / этот подход».
В трассировке: `"tag": "fact"`, `"sources": ["knowledge-base/insights/<id>.md"]`. Достижений из инсайта не бывает.
