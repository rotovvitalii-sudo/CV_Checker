# Структура для надиктовки письма

Письмо звучит как кандидат, только если он его надиктовал (`cover-letter`: ≥ 80% слов — его). Твоя
задача — не писать за него, а дать опору: в каком порядке говорить, что этой вакансии важно, какие
его кейсы и цифры подходят. Он смотрит на структуру и говорит своими словами.

## Жёсткие правила

1. **Никаких фраз письма.** `prompt` — подсказка или вопрос к кандидату по-русски, во втором лице:
   «Почему именно они: свяжи их задачу (запуск академии для трейдеров) с тем, как ты строил академию
   для брокера». Не «I am excited to…», не готовое предложение, которое можно зачитать.
   Не длиннее 200 символов.
2. **Факты только из базы.** Каждый пункт `facts` — короткий (до 120 символов): кейс, цифра, срок, роль —
   и `source`: путь к файлу, где этот факт написан: `knowledge-base/cards/<…>.md`,
   `knowledge-base/master-cv.md`, `output/<…>/CV.md`. Нет в базе — нет в фактах. Пометки `NDA` /
   `не использовать` / `предположение` в карточках — не брать.
3. **Пробелы честно.** Требования вакансии, которые нечем подтвердить, — в `gaps` по-русски
   («Опыт с B2B SaaS — в базе нет»). Не подменяй их похожими кейсами без пометки.
4. **Язык структуры — русский.** Названия компаний, продуктов и терминов вакансии — как в оригинале.
5. **Голос.** Загляни в 1–2 файла `knowledge-base/raw/`, чтобы подсказки были в его логике
   (что он обычно подчёркивает). Цитаты из raw в структуру не переносить.

## Процесс

### Шаг 0. Входы
- Вакансия: `vacancies/<…>.md` — главная задача роли, что компания строит, 3–5 ключевых требований.
- Если есть: `output/<…>/CV.md` (адаптированное CV — факты сверяй с ним), `output/<…>/02-match-report.md`
  (совпадения и пробелы), `output/<…>/report.md` (риски).
- База: `knowledge-base/master-cv.md`, `knowledge-base/cards/INDEX.md` → нужные карточки.

### Шаг 1. Главная задача вакансии
Одной фразой для себя: что этот человек будет делать первые полгода. Фит кандидата определяется
задачей, а не индустрией (`job-fit-search-brief.md`): ищи в базе кейс, где он делал ровно это.

### Шаг 2. Блоки
По умолчанию 4 блока — как в `cover-letter`:
1. **Зачем пишу и почему эта роль** — что в их задаче цепляет и почему это про него.
2. **История с результатом** — один-два кейса под главную задачу: что было, что сделал, цифра.
3. **Что закрываю и чего нет** — сильные совпадения и как сказать о главном пробеле (если стоит).
4. **Закрытие** — что предлагает дальше (разговор, конкретная тема).
Вакансия может поменять акценты (например, два блока историй), но не больше 5 блоков. В каждом блоке
2–4 факта; в блоке 4 факты можно не давать.

### Шаг 3. Результат
`output/<…>/04-letter-outline.json`:
```json
{
  "role_task": "главная задача роли одной фразой по-русски",
  "blocks": [
    {"title": "Зачем пишу и почему эта роль",
     "prompt": "подсказка по-русски, ≤ 200 символов",
     "facts": [{"text": "Академия для брокера: 0→1 за 6 месяцев", "source": "knowledge-base/cards/<…>.md"}]}
  ],
  "gaps": ["требование вакансии — чего нет в базе"],
  "length_hint": "надиктуй 2–3 минуты — письмо выйдет на 180–280 слов"
}
```
`output/<…>/04-letter-outline.md` — то же для чтения: блоки, подсказки, факты списком, «Пробелы».

### Шаг 4. Проверка
```bash
.venv/bin/python scorer/check_outline.py --outline "output/<…>/04-letter-outline.json" --json
```
`pass: false` → исправь замечания (длина подсказки, файл источника, английский текст в подсказке) и
проверь снова.

### Шаг 5. Итог в чат (по-русски, коротко)
Главная задача роли, сколько блоков и фактов, главные пробелы.
