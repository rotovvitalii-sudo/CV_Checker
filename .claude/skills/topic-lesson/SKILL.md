# Урок по теме перед собеседованием

Цель — чтобы кандидат уверенно говорил о предмете на интервью: знал термины, метрики, подходы и как о них спрашивают.
Это освежение знаний, а не курс с нуля: тема берётся там, где пересекаются его CV и вакансия.

## Жёсткие правила
1. **Урок — про предмет, не про кандидата.** Никаких фактов, цифр и достижений кандидата в тексте урока. Опыт кандидата —
   только в `meta.json → cards`: id карточек из `knowledge-base/cards/` (сверься с `INDEX.md`) и одна фраза «где это было».
   Нет подходящей карточки — пустой список, не выдумывай.
2. **Своими словами.** Ищи определения и практики в нескольких источниках (WebSearch / WebFetch), но текст пиши сам; не
   копируй абзацы и не цитируй длинно. Источники — в `meta.json → sources` (название и ссылка, 2–5 штук).
3. **Только проверяемое.** Формулы и метрики — общепринятые (как их считают в индустрии). Спорное — с пометкой
   «по-разному считают: …». Не придумывай статистику и бенчмарки без источника.
4. **Язык урока — английский** (лексика интервью), простой и разговорный, без LLM-штампов (см. скил `humanizer`).

## Урок → `knowledge-base/learning/<slug>/lesson.en.md`
~800–1200 слов, markdown, разделы строго с этими заголовками (на них ссылаются вопросы теста):
```
# <Title>
## What it is and why it matters
## Key metrics and formulas
## Frameworks and approaches
## Common mistakes
## How interviewers ask about it
## Glossary
```
- Метрики — с формулой и одной фразой, что считается хорошим знаком (без выдуманных бенчмарков).
- Фреймворки — 2–3, каждый: суть, когда применять, пример из типичной компании (не из опыта кандидата).
- «How interviewers ask» — 3–5 вопросов, у каждого одна строка «what they want to hear».
- Glossary — 10–15 терминов списком `- **term** — короткое объяснение`.

## Видео → `meta.json → video`
1. Найди одно видео на YouTube по теме: 5–30 минут, по возможности не старше 3 лет, канал практиков, известных компаний
   или конференций. Видео с главами (chapters) — в приоритете.
2. **Проверь ссылку** до записи: `WebFetch https://www.youtube.com/oembed?url=<ссылка>&format=json` — должен вернуться JSON
   с `title`. Не вернулся — ищи другое. Название в `meta` — ровно как в oEmbed.
3. Ключевые мысли — 3–5 пунктов по-английски, из глав, описания или субтитров, если удалось их получить (`source` — откуда).
   Не пересказывай то, чего нет. **Не удалось получить ничего, кроме названия — видео всё равно оставь** (`"key_points": []`,
   `"source": "none"`): описание, длительность и главы приложение подтянет само со страницы видео.
4. Не нашёл подходящего за 3 попытки — `"video": null`.

## Метаданные → `knowledge-base/learning/<slug>/meta.json`
```json
{"slug": "user-activation-saas", "title_en": "User activation in SaaS", "title_ru": "Активация пользователей в SaaS",
 "video": {"url": "https://www.youtube.com/watch?v=…", "title": "…как в oEmbed", "channel": "…", "minutes": 18,
           "key_points": ["…"], "source": "chapters|description|transcript|none"},
 "sources": [{"title": "…", "url": "https://…"}],
 "cards": [{"id": "<id карточки>", "where": "одна фраза по-русски, где кандидат с этим работал"}],
 "created": "YYYY-MM-DD"}
```

## Режим приложения
Запускается из веб-приложения в фоне: вопросы не задавай; slug, названия и контекст вакансии даны в промпте.
Пиши только два файла в `knowledge-base/learning/<slug>/`. Ответ в чат — одна строка по-русски.
Режим «только видео» (повторный поиск): обнови в `meta.json` только поле `video`, остальное не трогай.
