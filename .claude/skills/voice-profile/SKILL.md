# Голосовой профиль (knowledge-base/voice.md)

Цель — чтобы сгенерированное письмо звучало как кандидат, а агент не читал каждый раз 30+ надиктовок.

## Входы
- Все файлы `knowledge-base/raw/*.md`. Надиктовки писем (`*letter*`) — главный образец: как он пишет
  работодателю. Надиктовки кейсов — как он рассказывает о работе.
- Надиктовки — голосовой ввод на русском с ошибками распознавания. Смысл бери, ошибки не переноси.

## Правила
1. **Только манера, без фактов.** Ни названий компаний из его опыта, ни цифр, ни достижений —
   они живут в карточках и подтверждаются трассировкой письма. Пример оборота можно дать на нейтральном
   материале («I pushed this through with the team»), но не «I grew Northwind Learning to 15 countries».
2. **Обороты — его, а не красивые.** Только то, что встречается в надиктовках хотя бы дважды или
   явно характерно. Для каждого — русский оригинал (коротко) → близкий английский перевод.
   Не больше 12 слов подряд из одной надиктовки.
3. **Запреты конкретные.** Чего он не делает: например, не хвалит компанию общими словами,
   не говорит «passionate», не начинает с «I am writing to…». Бери из того, чего в надиктовках нет
   и что он вычёркивал (раздел «Что убрано» в `output/*/letter-summary.json`, если есть).
4. **Коротко.** 300–600 слов. Профиль читают перед каждым письмом.

## Формат файла
```
---
built: <YYYY-MM-DD>
sources: <файл1.md>, <файл2.md>, …   # все прочитанные надиктовки, через запятую
---
# Голос кандидата — для писем
## Как заходит в тему
## Порядок мысли
## Характерные обороты (рус → англ)
- «…» → "…"
## Ритм и длина фраз
## Чего он не говорит
## Как закрывает письмо
```

## Проверка
- В `sources` перечислены все файлы из `knowledge-base/raw/` (сервер по ним считает, сколько надиктовок
  появилось после сборки профиля).
- Нет названий компаний из его опыта и чисел из его достижений.
