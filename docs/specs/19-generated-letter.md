# C8 · Письмо, сгенерированное агентом

**Приоритет:** Should · **Зависит от:** C7 (структура письма), tailor-cv (адаптированное CV), humanizer
**Оценка:** ~1–1,5 дня
**Источник:** запрос кандидата 2026-10-15.

**Решения (подтверждены):**
- **два пути:** новая кнопка «Сгенерировать письмо» рядом с прежним «Сделать письмо» из надиктовки;
  правило «≥ 80% слов — из надиктовки» остаётся для надиктованных писем;
- для сгенерированного письма вместо правила 80% — **каждый факт со ссылкой на базу** (проверяет скрипт)
  и **голос по надиктовкам кандидата** (письма и кейсы в `knowledge-base/raw/`), humanizer обязателен;
- письмо **помечается «сгенерировано»**, в статистике видно, как на такие письма отвечают;
- **без поля-подсказки** агенту: только кнопка.

**Меняется жёсткий принцип проекта.** Сейчас в `CLAUDE.md` и скиле `cover-letter`: «≥ 80% слов письма —
из надиктовки, не пишет с нуля». После фичи: это правило для надиктованных писем; для сгенерированных —
«каждый факт из базы со ссылкой + голос по надиктовкам». Честность («только то, что есть в базе
знаний») не меняется.

## Problem Statement
Надиктовка письма под каждую вакансию — самый долгий ручной шаг: CV собирается агентом за 5–15 минут,
а письмо ждёт, пока найдётся время и настроение говорить. Структура (C7) помогает, но не снимает
работу. При этом материал для письма уже есть: кейсы в базе знаний, которые кандидат расширяет, и
5 надиктованных писем плюс ~30 надиктовок кейсов, по которым понятно, как он говорит.

## Goals
1. Письмо под вакансию готово одной кнопкой за ≤ 6 минут, без надиктовки.
2. 100% фактов сгенерированного письма подтверждены файлом базы (скрипт; иначе письмо не готово).
3. Сгенерированное письмо проходит humanizer (score ≤ 3), как и надиктованное.
4. Через месяц видно, отличается ли доля ответов на сгенерированные и надиктованные письма.

## Non-Goals
- **Отказ от надиктовки** — остаётся вторым путём (решено: два пути).
- **Поле-подсказка агенту** («акцент на подписке») — решено: только кнопка. Акценты задаёт структура C7.
- **Факты вне базы** — даже «очевидные». Нет в базе — нет в письме; пробел остаётся пробелом.
- **Письмо без адаптированного CV** — письмо идёт в пакете с CV и сверяется с ним, как сейчас.
- **Автоотправка** — письмо проверяешь и отправляешь сам (M1).

## User Stories
- Как кандидат, я хочу нажать «Сгенерировать письмо» и через несколько минут получить готовое письмо
  под вакансию, чтобы не надиктовывать каждый раз.
- Как кандидат, я хочу, чтобы письмо звучало как я — моими оборотами из прошлых надиктовок, а не
  шаблоном «I am excited to apply».
- Как кандидат, я хочу видеть, из каких кейсов взят каждый факт письма, чтобы быстро проверить, что
  ничего не придумано.
- Как кандидат, я хочу, чтобы письмо опиралось на структуру (C7): если её нет — агент делает её сам.
- Как кандидат, я хочу, чтобы новые кейсы, которые я добавляю в базу, сразу попадали в письма.
- Как кандидат, я хочу видеть в статистике, на какие письма отвечают чаще — сгенерированные или надиктованные.
- *Крайний случай:* письмо уже есть (надиктованное) — перед заменой подтверждение, прежнее сохраняется
  копией.
- *Крайний случай:* факт без источника или humanizer > 3 после доработки — письмо помечается «не готово»
  с причиной, как сейчас при проваленных проверках.
- *Крайний случай:* CV ещё не адаптировано — кнопка неактивна, подсказка «сначала адаптируй CV».

## Requirements

### P0
**P0-1. Скил `cover-letter-generate`** (новый, отдельно от `cover-letter`, чтобы не ломать правило 80%):
- входы: вакансия, `output/<…>/CV.md`, `02-match-report.md`, `report.md`, структура
  `04-letter-outline.json` (нет — сначала шаги скила `letter-outline`), карточки `knowledge-base/cards/`;
- **голос:** надиктовки писем (`knowledge-base/raw/*letter*`) и кейсов (`knowledge-base/raw/`) — порядок мысли,
  характерные обороты, длина фраз; цитировать надиктовки целыми кусками нельзя, только манеру;
- формат — правила 3, 6, 7 скила `cover-letter` (первое лицо, 180–280 слов, 3–4 абзаца, без шаблонов,
  не пересказывать CV); humanizer обязателен;
- выход: `output/<…>/Cover Letter.md` (тот же файл — экспорт и имя E1 работают как есть) +
  `04-generated-trace.json`: каждое предложение письма с тегом `fact` (и списком источников) или `link`
  (связка, мотивация без фактов) + `letter-summary.json` c `"mode": "generated"`.

**P0-2. Проверка `scorer/check_generated.py`:**
- текст трассировки совпадает с `Cover Letter.md` (письмо не правили мимо трассировки);
- у каждого предложения `fact` есть хотя бы один источник — существующий файл в `knowledge-base/` или
  `output/<…>/CV.md`;
- предложение с цифрой, процентом, годом, суммой или названием компании из базы не может быть `link`;
- длина 120–320 слов (или формат вакансии); `pass` + список замечаний.
- ✅ Письмо с выдуманной цифрой или с источником-несуществующим файлом не проходит.

**P0-3. Кнопка «Сгенерировать письмо»** в блоке «3 · Сопроводительное письмо»:
- рядом с «Сделать письмо» (из надиктовки); надиктовка для неё не нужна;
- доступна после адаптации CV; через `agentReady`; прогресс, ошибки, журнал S5, уведомление C3;
- в подсказке — условная стоимость и время (≈ $1–2, 3–6 минут; первый прогон — $0,79 за 63 с);
- если письмо уже есть — подтверждение; прежнее сохраняется как `Cover Letter (prev).md`.

**P0-4. Показ письма:**
- метка «сгенерировано» (или «из надиктовки») у письма;
- для сгенерированного вместо «доля твоих слов» — «факты с источником N/N» и humanizer;
- под письмом — список «Откуда факты»: предложение → карточки (свёрнут по умолчанию);
- проверки не прошли — «не готово» с причиной.

**P0-5. Пометка в отправке и статистике:**
- при отметке отправки (M1) в запись `sent` пишется `letterMode: generated | dictated | none`;
- в статистике (S3) разрез «Письмо: сгенерировано / надиктовано / без письма» — доля ответов.

**P0-6. Документация принципа:** `CLAUDE.md` (жёсткие принципы, компонент 4), скил `cover-letter`
(ссылка на второй путь), сводка спек.

## Success Metrics
- **Leading (2 недели):** ≥ 70% писем сгенерированы; 100% сгенерированных проходят проверку фактов
  с первого или второго прогона; humanizer ≤ 3; медиана «CV готово → письмо готово» ≤ 10 минут.
- **Lagging (1–2 месяца):** доля ответов на сгенерированные письма не ниже, чем на надиктованные
  (разрез S3; выводы — при ≥ 5 отправках в каждой группе).

## Open Questions
- *(ты, неблокирующий)* Если сгенерированное письмо понравилось, а ты поправил пару фраз руками — считать
  его «сгенерированным» или «смешанным»? Предлагаю: «сгенерировано», правки руками не отслеживаем.
