# S3 · Статистика воронки

**Приоритет:** Should · **Зависит от:** M1 (даты, каналы, исходы)
**Аналог в Aircareer:** Applications → Stats (Total, Applied, Interviews %, Offers %, Pipeline, response rate)

## Problem Statement
Главная гипотеза поиска — «фит определяется задачей, а не индустрией»: заявки с высоким task-fit
должны получать ответы чаще. Сейчас проверить это нельзя: нет данных об исходах и нет экрана, где
они сводятся. Без этого невозможно понять, что работает — каналы, тип ролей, адаптация CV — и куда
тратить время.

## Goals
1. Видно, сколько заявок отправлено за неделю и месяц, доля ответов и интервью — без ручного счёта.
2. Видна разбивка исходов по task-fit (≥ 7 против < 7), по каналу и по наличию адаптированного CV —
   это прямая проверка гипотезы брифа.
3. Цифры совпадают с доской и таблицей (один источник данных).

## Non-Goals
- **Графики во времени** (тренды по неделям) — при 10–30 заявках шумно; P2.
- **Сравнение с рынком / бенчмарки** — нет данных.
- **Статистика ленты** (S1) — отдельно, если понадобится.

## User Stories
- Как кандидат, я хочу видеть итоги: всего, отправлено, ответили, интервью, офферы — числом и долей.
- Как кандидат, я хочу видеть воронку по стадиям, чтобы понять, где теряются заявки.
- Как кандидат, я хочу видеть долю ответов по фиту, каналу и по «адаптировано / базовое CV», чтобы
  понять, что повышает шансы.
- Как кандидат, я хочу видеть медиану дней до ответа.
- *Крайний случай:* меньше 5 отправленных — показываем числа, но с пометкой «мало данных для выводов».

## Requirements

### P0
**P0-1. Экран «Статистика»** (вкладка на главном экране рядом с «Таблица / Доска»):
- Плитки: всего · отправлено · ответили (% от отправленных) · интервью (%) · офферы.
- Воронка: Готовится → Отправлено → Ответили → Интервью → Оффер, число и доля.
- Разрезы: task-fit ≥ 7 / < 7; канал; адаптированное CV / нет; доля ответов в каждом.
- Медиана дней от отправки до первого ответа.
- ✅ Числа считаются из `history` и `sent` заявок; совпадают с доской.
- ✅ При n < 5 в разрезе — серый текст «мало данных».

### P1
- Фильтр периода: всё время / 30 дней / 7 дней.
- Экспорт сводки в markdown (для отчёта самому себе).

### P2
- Тренд отправок и ответов по неделям.
- Связь с калибровкой фита: заявки с фитом ≥ 7, которые ты отклонил, и наоборот (раздел F `job-scout`).

## Что уже есть в коде
- Фит и баллы — `app.fit`; матч Master — `web/master.js`; статусы — `web/store.js`.
- История статусов и данные отправки появятся в M1.

## Success Metrics
- **Leading:** экран открывается раз в неделю.
- **Lagging (6–8 недель):** есть ответ на вопрос «отвечают ли на task-fit ≥ 7 чаще» хотя бы на 20
  отправленных заявках.

## Решения и статус (2026-10-13)
- «Ответ» — любая реакция после отправки, включая отказ (авто-отказ от живого в данных не отличить);
  отказы показываются отдельной цифрой.
- P0 реализован только во фронтенде (`web/public/app.js` → `statsView()`, `appStats()`): вкладка
  «Статистика» в «Все заявки» — плитки, строка-вывод по гипотезе «фит 7+», воронка по самому
  дальнему этапу из истории, разрезы по фиту / каналу / пакету, медиана дней до ответа,
  «мало данных» при n < 5. Проверено на 11 тестовых заявках в копии проекта — цифры совпали с ручным
  подсчётом. P1 (фильтр периода, экспорт) — не сделано.
