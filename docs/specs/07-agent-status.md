# S5 · Статус и расход агента

**Приоритет:** Should (делаем рано — маленькая и убирает тихие сбои) · **Зависит от:** —
**Аналог в Aircareer:** счётчик «245 left», Profile → Plan & usage («This month»)

## Problem Statement
Все шаги конвейера выполняет `claude -p` на твоей подписке. 12 октября агент не работал, потому что
CLI не был залогинен, а приложение узнало об этом только после запуска задачи. Кроме того, не видно,
сколько запусков и денег уходит на конвейер — сколько стоит одна заявка.

## Goals
1. Проблема с агентом (не залогинен, CLI не найден) видна в шапке до запуска задачи — 100% случаев.
2. Видно число запусков и стоимость за текущий месяц и в среднем на заявку.
3. Проверка статуса не тратит лимит подписки (не вызывает модель).

## Non-Goals
- **Лимиты и блокировка запусков** — инструмент личный, решаешь ты.
- **Логин из приложения** — авторизация остаётся в терминале (`claude auth login`).
- **Точная биллинговая отчётность** — показываем `total_cost_usd` из ответов агента как оценку.

## User Stories
- Как кандидат, я хочу видеть в шапке, готов ли агент к работе, чтобы не запускать задачу впустую.
- Как кандидат, я хочу при проблеме видеть понятную инструкцию («выполни `claude auth login`»).
- Как кандидат, я хочу видеть, сколько задач агента и на какую сумму выполнено в этом месяце и
  сколько в среднем стоит одна заявка (фит + CV + письмо).
- Как кандидат, я хочу видеть историю последних запусков: тип, вакансия, длительность, стоимость, итог.
- *Крайний случай:* статус не удалось проверить (CLI завис) — «статус неизвестен», не красный.

## Requirements

### P0
**P0-1. Проверка статуса** — `claude auth status` (JSON, без вызова модели) при старте сервера и
раз в 5 минут; кэш. `GET /api/agent/status` → `{ok, loggedIn, authMethod, version, checkedAt, error}`.
**P0-2. Индикатор в шапке** вместо заглушки: зелёная точка «Агент на связи» / красная «Агент не
залогинен» с подсказкой и кнопкой «Проверить снова». Кнопки запуска агента при `loggedIn=false`
показывают предупреждение до запуска.
- ✅ Given CLI не залогинен, When открываю приложение, Then в шапке красный статус и инструкция.
**P0-3. Журнал запусков** — каждая завершённая задача пишет строку в `web/data/runs.jsonl`:
`{at, kind, target, durationMs, costUsd, ok, error}` (данные уже есть в `agent.js`).
**P0-4. Расход** — экран или поповер из шапки: за месяц (запуски, $, по типам), средняя стоимость
заявки, последние 20 запусков.
- ✅ Суммы совпадают с журналом; задачи прошлых дней (до фичи) не учитываются — честно пишем «с <даты>».

### P1
- Мягкий месячный бюджет с предупреждением при 80%.
- Расход на карточке вакансии («эта заявка: $0.84»).

### P2
- Выбор модели для фоновых задач (дешевле для фита, сильнее для CV).

## Что уже есть в коде
- `web/agent.js`: `job.cost` из `total_cost_usd`, `started` / `finished`, нормализация ошибки
  авторизации; `publicJob()`.
- Заглушка индикатора: `web/public/index.html` → `.agent-status`.

## Success Metrics
- **Leading:** ноль задач, упавших из-за авторизации без предупреждения заранее.
- **Lagging:** известна средняя стоимость заявки; решение о модели для фона принимается на данных.

## Статус (2026-10-13)

запуском задачи), защита `agentReady` на всех запросах, которые запускают агента (409 с инструкцией),
журнал `web/data/runs.jsonl` (при первом запуске восстановлен из логов — история неполная),
экран `#/agent`, индикатор в шапке. Из P1 сделан расход на карточке заявки; бюджет — нет.

а лимит подписки CLI не показывает.
