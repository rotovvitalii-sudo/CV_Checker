# S1 · Лента вакансий: Save / Skip

**Приоритет:** Should · **Зависит от:** — · **Связано с:** `job-scout`, `job-search/fetch.py`
**Аналог в Aircareer:** Jobs (Grid / Swipe), Recently skipped, Hidden jobs, Apply on site

## Problem Statement
Сейчас вакансии попадают в приложение только вручную. `fetch.py` уже умеет тянуть сотни вакансий с
Himalayas и RemoteOK, но результат лежит в JSON-файлах, и смотреть его неудобно. Замер на 1315
вакансиях показал, что поток A почти пуст. Прогон 2026-10-02 дал **0 кандидатов**: словарь отбора
строгий, и без удобного просмотра «почти подходящих» хорошие вакансии теряются.

## Goals
1. Разбор 20 вакансий из ленты (сохранить / пропустить) — ≤ 5 минут.
2. Каждая сохранённая вакансия автоматически получает фит и ключи — без ручной вставки текста.
3. В ленте никогда не появляется вакансия, которая уже есть в заявках, в корпусе или была пропущена.
4. Лента не пустая, даже когда строгий словарь не нашёл никого: есть раздел «почти подходят».

## Non-Goals
- **Сбор с LinkedIn и сайтов с логином** — запрещено правилами площадок и принципами проекта.
- **Фит всех вакансий ленты агентом** — дорого. Фит запускается только при «Сохранить».
- **Свайп-жест** — кнопки и клавиши (S / X) решают ту же задачу на десктопе.
- **Изменение словаря отбора из интерфейса** — словарь крутится в `classify.py`, это работа с калибровкой.

## User Stories
- Как кандидат, я хочу открыть ленту новых вакансий с открытых досок, отсортированную по сигналу
  фита, чтобы не искать их вручную.
- Как кандидат, я хочу по каждой вакансии видеть название, компанию, формат, зарплату, найденные
  фит-термины и первые строки описания, чтобы решить за несколько секунд.
- Как кандидат, я хочу нажать «Сохранить», чтобы вакансия ушла в заявки и агент оценил фит.
- Как кандидат, я хочу нажать «Пропустить», чтобы вакансия больше не появлялась, и вернуть её из
  «Недавно пропущенных», если ошибся.
- Как кандидат, я хочу открыть вакансию на сайте источника.
- Как кандидат, я хочу обновить ленту кнопкой, чтобы подтянуть свежие вакансии.
- *Крайний случай:* источник отдаёт 429 (лимит частоты) — лента показывает, что получено, и
  сообщает, что Himalayas ограничил запросы.
- *Крайний случай:* строгий фильтр дал 0 — показываем «почти подходят» (роль совпала, сигнала
  задачи нет, или наоборот).

## Requirements

### P0
**P0-1. Экран «Лента»** (пункт меню «Поиск вакансий» вместо заглушки). Две секции:
«Подходят» — кандидаты `fetch.py` (поток A/B); «Почти подходят» — вакансии из сырья, прошедшие
одну из двух осей `classify.py`. Карточка: роль, компания, источник, давность, формат/локация,
зарплата (если есть), чипы фит-терминов, 3 строки описания.
- ✅ Пустая выдача — понятное пустое состояние и кнопка «Обновить».

**P0-2. «Сохранить»** — создаёт входящую заявку с текстом описания и ссылкой и запускает
существующий шаг фита (`POST /api/vacancies`). Карточка уходит из ленты.
- ✅ Через ~1–2 минуты вакансия появляется на главном экране с фитом.

**P0-3. «Пропустить»** — вакансия скрывается; ключ пишется в `job-search/seen.json` (или отдельный
`skipped.json`) с датой. «Недавно пропущенные» показывают последние 30 и позволяют вернуть.
- ✅ Пропущенная не возвращается после «Обновить».

**P0-4. «Обновить ленту»** — запускает `fetch.py` в фоне (с курсором, паузами 1.2 с), показывает
прогресс и итог «+N новых».
- ✅ Повторный запуск в тот же день не дублирует вакансии (дедуп по `seen.json`).

### P1
- Сортировка: сигнал фита / свежесть; фильтр по источнику.
- Клавиши S (сохранить), X (пропустить), O (открыть).
- Счётчик в меню: «Поиск вакансий · 12 новых».

### P2
- Новые источники (dou.ua, justjoin.it RSS, HN Who is hiring).
- Поток B (сигналы компаний) отдельной вкладкой с таблицей из `signals.md`.

## Что уже есть в коде
- `job-search/fetch.py` (источники, курсор, сырьё в `raw/`, кандидаты в `candidates/<дата>.json`,
  поле `fit_hits`), `job-search/classify.py` (`classify(job)`), `job-search/replay.py` (прогон кэша
  через словарь без запросов), `seen.json`, `cursor.json`.
- Добавление вакансии и фит: `POST /api/vacancies` в `web/server.js`, промпт `prompts.fit`.

## Success Metrics
- **Leading:** ≥ 3 сохранённые вакансии из ленты в неделю; время на 20 карточек ≤ 5 минут.
- **Lagging (месяц):** доля заявок из ленты среди всех ≥ 30%; среди сохранённых доля с фитом ≥ 7 ≥ 40%
  (иначе сигнал ленты плохой — правим словарь).

## Решения и статус (2026-10-13)
- Разделы: «Подходят» (поток A/B) и «Продуктовые роли» (роль продуктовая, задачи обучения нет).
  «Задача без роли» не показываем — замер на 1315 вакансиях: 16 штук, почти всё шум.
- Пропуски — отдельно, `web/data/feed-skipped.json` (`seen.json` = «уже скачано»).
- `fetch.py --fresh`: Himalayas с самой новой страницы до первой страницы без новых, курсор
  глубокого обхода не трогается. Первый прогон: 414 вакансий, 316 новых, +5 продуктовых ролей.
- P0 реализован: `job-search/feed.py`, `web/feed.js`, `/api/feed*`, экран `#/feed` (пункт меню
  «Поиск вакансий»). «Сохранить» создаёт входящую заявку и запускает фит (≈ $0.5–0.7).
  P1 (клавиши, счётчик новых, сортировка) — не сделано.

## Фильтр «только США» (2026-10-26)
Вакансии, где все локации в США или текст требует права работать / жить в США (переезд, резидентство), в ленту не попадают —
во всех разделах (Подходят, Продуктовые, EdTech, FinTech). Если среди локаций есть хоть одна не в США (London, EMEA, Global,
Americas, Canada) — вакансия остаётся. Логика — `job-search/classify.py` → `us_only()`, фикстуры `job-search/fixtures/us_only.json`
(проверяются в `calibrate_dict.py`). Под заголовком ленты — «Скрыто N вакансий только для США» со списком; выключить —
«Профиль» → «Вакансии только для США» (`profile.json → exclude_us_only`). На первом прогоне скрыто 54 из 212.
