# V3 · Диагностика тишины: почему не отвечают на отклики

**Приоритет:** Must · **Зависит от:** S3 «Статистика», W6 (этапы), W1 (`top_third`), M1 (`sent.at`), фит (`date_posted`, `work_format`), V1, V2 (по желанию)
**Оценка:** ~1 день · **Источник:** запись интенсива «Шлях Самурая №15», блоки 1–2 (≈ 0:30, 0:35, 0:52).

## Problem Statement
Главная проблема кандидата — мало ответов на отклики: воронка рвётся на первом этапе («тишина»). Интенсив называет три
причины тишины: стреляешь не туда (минимум вакансии не закрыт); CV не показывает главное в верхней трети и не адаптировано;
тебя не находят и/или ты подаёшься поздно (отклики разбирают пачками, ранние — выше в списке). Плюс формат: на remote
приглашают почти вдвое реже, чем на hybrid (3,5% против 6% по Huntr). Предлагается самопроверка «5 последних откликов»
руками. Все нужные данные у нас уже есть по каждой отправленной заявке, но никто их не сводит, и кандидат гадает
(«рынок умер», «английский»), вместо того чтобы видеть линию в фактах.

## Goals
1. В «Статистике» — блок «Почему тишина»: по последним 10 отправленным заявкам — таблица из 5 проверок и вывод «главная вероятная причина» по правилам (без агента, бесплатно).
2. Новые разрезы доли ответов: по формату работы, по скорости подачи (дни от публикации до отправки), по закрытому минимуму (V2) и наличию сообщения (V1).
3. Каждый вывод ведёт к действию в приложении (какой фильтр включить, что переделать), а не к общему совету.

## Non-Goals
- **Агент-аналитик** — правила простые, данных мало; агент добавил бы цену и «версии» вместо фактов.
- **Утверждения при малой выборке** — разрез показывается с числами всегда, вывод «отвечают чаще / реже» — только при n ≥ 5 в каждой группе (как гипотеза S3).
- **Диагностика поздних этапов** — это W6 (воронка и отказы); здесь только «отклик → первый ответ».

## User Stories
- Как кандидат, я хочу увидеть по 10 последним откликам: закрыт ли минимум (фит 7+), видна ли задача в верхней трети, было ли CV адаптировано, через сколько дней после публикации я подался, какой формат — и где большинство «нет».
- Как кандидат, я хочу получить вывод: «7 из 10 — подано через 10+ дней после публикации: подавайся в первые 2–3 дня (включи уведомления о свежих вакансиях)».
- Как кандидат, я хочу видеть «на remote ответили 1 из 12, на hybrid — 2 из 5», чтобы решить, расширять ли поиск.
- *Крайний случай:* дата публикации неизвестна — проверка «скорость» для заявки пустая, а не «плохо».

## Requirements
### P0
- **P0-1. Проверки по заявке** (сервер, из уже сохранённых данных):
  (1) **минимум** — фит ≥ 7 (позже — «минимум закрыт» из V2);
  (2) **верхняя треть** — `cv.topThird.pass` у адаптированного CV;
  (3) **адаптировано** — отправлено с пакетом (`sent.package`) и CV собрано под вакансию;
  (4) **скорость** — дни от `date_posted` до `sent.at`: ≤ 3 — ✓, 4–7 — частично, > 7 — ✗, нет даты — «—»;
  (5) **формат** — remote / hybrid / onsite (информационно).
  Плюс отметка «ответили / нет / ещё ждём» (ждём — отправлено < `no_reply_days`).
- **P0-2. Блок «Почему тишина»** в «Статистике» (над воронкой): таблица последних 10 отправленных (компания, 5 проверок, итог);
  под таблицей — до 2 выводов по правилам: проверка с наибольшим числом ✗ среди заявок без ответа (≥ 50% из них) → причина +
  действие: минимум → «стреляешь не туда: подавайся на фит 7+, используй фильтр „фит 7+“»; верхняя треть → «главное не видно
  сразу: пересобери CV (W1)»; не адаптировано → «адаптируй под вакансию»; скорость → «подаёшься поздно: свежие вакансии —
  в первые 3 дня»; иначе — «явной причины нет — смотри разрезы ниже».
- **P0-3. Новые разрезы доли ответов** (те же таблицы, что S3, `sliceRows`): по формату работы; по скорости подачи
  (≤ 3 дн. / 4–7 / > 7 / нет даты); по фиту 7+ (уже есть) — рядом для сравнения.
- **P0-4. Учитывает фильтр периода** (S3 P1: всё время / 30 / 7 дней).
- ✅ На текущих отправленных заявках вывод совпадает с ручной самопроверкой по 5 последним.

### P1
- Разрезы по закрытому минимуму (V2) и по наличию сообщения к отклику (V1) — как только данные появятся.
- Ссылка из вывода сразу в нужное место: фильтр ленты, заявка без адаптированного CV, настройка уведомлений.
- Тот же вывод коротко — в еженедельном итоге «Моя неделя» (W7).

### P2
- «Скорость» в ленте: метка «опубликовано < 24 ч» и уведомление о свежих сильных вакансиях (отдельная фича — совет 4 из разбора видео).

## Success Metrics
- **Leading:** блок открыт ≥ 1 раза в неделю; после вывода «поздно» медиана «дней до подачи» падает до ≤ 3 за 2 недели.
- **Lagging:** доля первых ответов растёт через месяц (сейчас ≈ 6% от отправленных).
