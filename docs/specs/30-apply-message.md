# V1 · Короткое сообщение к отклику

**Приоритет:** Should · **Зависит от:** быстрый фит (`prompts.fitQuick`, `runJob({ system })`), адаптированное CV (`output/<…>/CV.md`), V2 («что болит» — по желанию)
**Оценка:** ~0,5 дня · **Источник:** запись интенсива «Шлях Самурая №15», блок 3 (`knowledge-base/research/…-konspekt.md`, ≈ 1:28).

## Problem Statement
Во многих формах (Djinni, Workable, Ashby, LinkedIn Easy Apply, письмо рекрутеру) есть поле «сообщение» на 2–5 строк.
По словам автора интенсива, рекрутеры читают его чаще, чем CV: это первые секунды знакомства. Сейчас у нас есть
только полноценное сопроводительное письмо (180–280 слов) — для такого поля оно длинное, а писать короткое сообщение
руками под каждую вакансию долго, и кандидат его либо пропускает, либо отправляет шаблон «I'm very motivated».

## Goals
1. Для любой заявки с адаптированным CV (или Master CV) — готовое сообщение из 3 частей за ≤ 30 с и ≈ $0.005.
2. 0 фактов вне базы знаний: каждая цифра в сообщении есть в CV, по которому оно написано.
3. Сообщение укладывается в выбранный лимит (по умолчанию 500 символов) и проходит humanizer (`check_humanize.py`, ≤ 3).

## Non-Goals
- **Отправка сообщения** — кандидат копирует и отправляет сам (как все артефакты).
- **Замена сопроводительного письма** — письмо остаётся для форм, где нужно письмо.
- **Сообщения людям в компании** — это W4 (`outreach`), другой жанр: там нельзя просить о работе.
- **Версии на других языках** — английский; польский / украинский — P2.

## User Stories
- Как кандидат, я хочу нажать «Сообщение к отклику» и получить 3 предложения: роль и почему именно эта вакансия, один мой результат под её главную задачу, готовность поговорить — чтобы вставить в поле формы.
- Как кандидат, я хочу задать лимит символов поля (Djinni, LinkedIn), чтобы сообщение влезло.
- Как кандидат, я хочу сгенерировать ещё один вариант, если первый не нравится, и поправить текст прямо на месте.
- *Крайний случай:* адаптированного CV ещё нет — сообщение пишется по Master CV, с пометкой.

## Requirements
### P0
- **P0-1. Генерация одним ходом без инструментов** (тот же механизм, что быстрый фит): задача `applymsg`, модель по умолчанию
  Haiku (экран «Агент» → «Модель по задачам»). В промпт сервер кладёт: текст вакансии (или `current_task` + `what_you_do`
  + «что болит» из V2, если есть), `CV.md` (или `base-cv.md`), голосовой профиль `knowledge-base/voice.md` (если есть),
  правила humanizer коротко, лимит символов.
- **P0-2. Формат ответа:** `{"message": "...", "facts": [{"text": "...", "source": "CV"}]}`. Структура: (1) роль + почему эта вакансия —
  через её задачу, не через комплименты компании; (2) один результат с цифрой, связанный с главной задачей; (3) готовность
  поговорить. Без «I'm excited / motivated / passionate», без пересказа CV, без приветствия, если лимит < 300.
- **P0-3. Проверки на сервере (без агента):** длина ≤ лимита; каждое число в сообщении встречается в тексте CV, по которому
  оно написано; `check_humanize.py ≤ 3`. Не прошло — одна повторная генерация с указанием ошибки; снова не прошло — показать
  с предупреждением.
- **P0-4. Хранение:** `output/<…>/06-apply-message.json` (`message`, `limit`, `cv`, `model`, `at`, предыдущий вариант).
- **P0-5. Интерфейс:** в блоке «Отправка» на странице заявки — «Сообщение к отклику»: поле лимита (по умолчанию 500), текст,
  счётчик символов, «Копировать», «Ещё вариант». Текст можно поправить на месте (сохраняется).
- ✅ На 5 реальных заявках: сообщение ≤ лимита, все цифры из CV, humanizer ≤ 3, сверка глазами.

### P1
- Пресеты лимита: Djinni, LinkedIn, Workable/Ashby «cover message», e-mail (короче / длиннее).
- Кнопка «Сообщение» в ленте сразу после сохранения вакансии (по Master CV) — чтобы подать в первые часы (связано с V3).
- В C11 «Подать на сайте»: поле «message / additional information» формы заполняется этим сообщением.

### P2
- Польская и украинская версии.

## Success Metrics
- **Leading:** сообщение сгенерировано в ≥ 80% отправленных заявок за 2 недели; правок руками ≤ 1 из 3.
- **Lagging:** доля ответов у заявок с сообщением выше, чем без (разрез в «Статистике», V3).
