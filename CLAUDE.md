# CV Checker — агентная система адаптации CV и сопроводительных писем

## Для кого
Личный инструмент одного кандидата (дальше — «кандидат» или «владелец»; «я» в тексте — тоже он).
Кто он, его опыт и личный контекст поиска — в `CLAUDE.local.md` (не в git). На чистом клоне —
демо-кандидат: `npm run demo:setup` кладёт `examples/demo/` на место личных папок.

Артефакты для работодателей (CV, cover letters) — по-английски; подсказки и отчёты для кандидата — по-русски.

## Цель системы
На входе — одна или несколько вакансий и мои надиктовки. На выходе — готовые пакеты
(адаптированное CV, сопроводительное письмо, отчёт о совпадении и пробелах) для проверки глазами.
Моё участие минимально.

## Структура проекта
```
knowledge-base/
  master-cv.md        # мастер-CV в текстовом виде (источник истины по фактам) + «Открытые вопросы»
  base-cv.md          # мастер-CV в формате CV.md — копия активной версии основного профиля (C18).
                      #   Правится через веб (экран Master CV). База адаптации — выбранный профиль, не обязательно этот файл
  master-cv/versions/vNNN/  # история Master CV: base-cv.md, meta.json, исходник, Master CV.docx/.pdf
  master-cv/active.json     # реестр профилей: основной профиль, активная версия каждого (C18)
  raw/                # сырые надиктовки как есть — нужны, чтобы сохранять мой голос в письмах
  cards/              # карточки опыта, по одной на проект/кейс
  cards/INDEX.md      # реестр карточек для быстрого поиска и защиты от дублей
job-fit-search-brief.md     # стратегия поиска вакансий: инсайты, рубрика, источники
job-search/
  fetch.py            # шаг 1: тянет вакансии с API досок, делит на поток A и поток B
  raw/, candidates/   # сырьё и отобранные кандидаты по датам
  seen.json, cursor.json  # чтобы не обходить одно и то же дважды
  corpus/jobs.jsonl   # все оценённые вакансии, включая отсеянные (материал для анализа рынка)
  calibration/        # эталоны для проверки рубрики
  digests/            # ежедневные дайджесты
  signals.md          # поток B — компании, которые строят академию без вакансии
test-tasks/           # тестовые задания (C14): <slug>/ (задание, рабочая папка, план, разбор), PLAYBOOK.md, LIBRARY.json
vacancies/            # вакансии в .md, имя файла: `Роль - Компания.md`
output/<Роль - Компания>/   # CV.docx, cover letter, отчёт о совпадении и пробелах
scorer/               # собственный чекер
web/                  # веб-интерфейс (MVP): server.js, agent.js, store.js, public/
.claude/skills/       # скилы проекта
Master_CV.pdf         # оригинал мастер-CV
```

## Компоненты (строим по очереди)
1. **Скил-интервьюер** — `.claude/skills/case-interview/` ✅ готов
2. **Конвейер CV** — `.claude/skills/tailor-cv/` ✅ готов (первый прогон: покрытие 91%, оценка «рекрутера» 4/5).
   Вакансия → `01-requirements.md` + `01-keywords.json` → `02-match-report.md` → `CV.md` →
   `CV.docx` (скрипт `build_docx.js`) → чекер → до 3 итераций → `report.md`.
   Пачки вакансий — параллельно через субагентов (см. SKILL.md).
3. **Собственный чекер** — ✅ часть (а): `scorer/check_cv.py` (парсинг .docx, структура ATS,
   рендер в PDF и счёт страниц, покрытие must/nice), `scorer/check_diff.py` (дрейф от базового CV,
   порог 20%), `scorer/check_letter.py` (доля надиктовки в письме, порог 80%). Часть (б) — оценка «рекрутера» делается LLM
   внутри скила по рубрике из 5 пунктов, дописывается в `03-score.md`.
   Коммерческий чекер (Jobscan и т.п.) не автоматизируем через браузер — нет публичного API,
   это хрупко и нарушает их условия. Используем вручную для калибровки своего чекера
   на 10–15 вакансиях (сравнивать `03-score.md` с оценкой Jobscan).
4. **Скил сопроводительных писем** — `.claude/skills/cover-letter/` ✅ готов.
   Входы: вакансия + `output/<...>/CV.md` + надиктовка. Переводит на английский, сверяет с CV
   и базой, структурирует и сокращает; **≥80% слов письма — из надиктовки** (проверяет
   `scorer/check_letter.py` по файлу трассировки `04-cover-letter-trace.md` с тегами `[D]`/`[A]`).
   Не пишет с нуля. Финальная версия **обязательно** проходит через скил `humanizer`.
   Выход: `output/<...>/Cover Letter.md`.
   **Структура для надиктовки** — скил `.claude/skills/letter-outline/` (кнопка «Сгенерировать структуру» в блоке
   письма): 4–5 блоков с подсказками по-русски и фактами из базы со ссылкой на файл, пробелы, ориентир длины.
   Не пишет фраз письма; проверка `scorer/check_outline.py`. Для `cover-letter` — только порядок блоков.
   **Письмо без надиктовки** (C8) — скил `.claude/skills/cover-letter-generate/` (кнопка «Сгенерировать письмо»):
   по структуре, CV и карточкам; голос — по надиктовкам в `knowledge-base/raw/`. Вместо правила 80% —
   трассировка `04-generated-trace.json`: каждое предложение `fact` (с файлом-источником) или `link`;
   проверка `scorer/check_generated.py`, humanizer обязателен. В `letter-summary.json` — `"mode": "generated"`,
   при отправке пишется `sent.letterMode`, в статистике — разрез «сгенерировано / надиктовано».
   **Голосовой профиль** — скил `.claude/skills/voice-profile/` → `knowledge-base/voice.md` (манера без фактов); при наличии
   `cover-letter-generate` читает только его. Обновляется кнопкой в «База кейсов → Надиктовки писем».
   **Файлы письма** (C10): `scorer/build_letter.py` → `Cover Letter.docx` / `.pdf` в стиле CV (шапка, дата, 1 страница);
   в приложении — «PDF», «DOCX», «CV + письмо», имя `Cover_Letter_<Имя_Фамилия>_<Позиция>_<Компания>`.
4a. **Humanizer** — `.claude/skills/humanizer/` ✅ готов. Чистит английский текст от признаков
   машинного письма (LLM-лексика, шаблоны писем, тире, однообразный ритм предложений), не меняя
   смысла и голоса. Проверяет `scorer/check_humanize.py`, порог `score ≤ 3`.
   Такого скила нет в галерее Claude — он собран локально в проекте.
5. **Job Scout (поиск вакансий по фиту)** — `.claude/skills/job-scout/` ✅ MVP готов.
   Контекст и стратегия — `job-fit-search-brief.md` (читать перед первым скорингом).
   Вакансия → извлечение по схеме → баллы по рубрике (задача 0–4 · домен 0–2 · роль 0–2 ·
   логистика 0–2) → `scorer/score_job.py` (жёсткие фильтры, пороги, дедуп, корпус) →
   ≥7 сохраняется в `vacancies/` → дайджест. Калибровка на 6 эталонах проходит.
   **Главный принцип: фит определяется задачей, а не индустрией** — сильнее всего кандидат подходит компании,
   которая строит то, что он уже строил (у владельца — академия/LMS), независимо от отрасли.
   **Словарь отбора — `job-search/classify.py`** (единственное место, где крутятся критерии),
   фикстуры — `job-search/calibrate_dict.py` (10 штук, все проходят: три эталонные вакансии → поток A,
   брокер и SaaS, строящие академию → поток B, внутреннее обучение сотрудников и учителя → мимо).
   Быстрая итерация без запросов к API: `job-search/replay.py` гоняет кэш через текущий словарь.
   **Только США — не в ленту** (2026-10-26): `classify.py` → `us_only()` — все локации в США (города, штаты, «Remote - USA»,
   «Lake Mary, FL») или в тексте требуется право работать / жить в США, а других локаций нет. `feed.py` такие не показывает
   и отдаёт `hidden_us` («Скрыто N» в ленте); выключается в профиле (`exclude_us_only`). Фикстуры — `fixtures/us_only.json`.

   **Три урока отбора (2026-10-02):**
   1. Термин нельзя искать по всему тексту вакансии — «training», «investment» живут в блоках
      бенефитов и EEO. Роль берётся из заголовка, домен — из названия компании и первых 800 символов.
   2. Для потока A задача обучения в тексте **обязательна**, иначе ловится любой продакт в финтехе.
   3. **Сигнал потока B инвертирован:** EdTech, нанимающий инструкционного дизайнера, — это его
      обычная работа. Сильный сигнал — когда обучение начинает строить НЕ образовательная компания
      (брокер, финтех, крипто, SaaS). Это ровно паттерн, по которому случались прошлые наймы владельца.

   **Замер на 1315 вакансиях:** продуктовых ролей 45 (3.4%), из них с задачей обучения — **ноль**;
   ролей «строит обучение» — 6. Вывод: поток A на публичных досках почти пуст, нужен объём и другие
   источники (новости о выходе брокеров на новые рынки, раунды EdTech).
   Источники: Himalayas — 101K вакансий, курсорная пагинация по 20, лимит частоты (429) → паузы
   1.2 с и сохранение курсора. RemoteOK — ~100 последних. Remotive отдаёт 16, бесполезен.

## Жёсткие принципы
- **Честность:** в CV и письма попадает только то, что есть в базе знаний. Требования вакансии,
  которые нечем подтвердить, идут в отчёт как «пробелы» — решение о добавлении кейса за мной.
- **Письмо — два пути агента и своё (C16).** Надиктованное (`cover-letter`): ≥ 80% слов — из надиктовки. Сгенерированное
  (`cover-letter-generate`): каждый факт — со ссылкой на файл базы, голос — по моим надиктовкам, humanizer.
  Ни в одном пути нет фактов вне базы знаний.
- **Порог, а не максимум:** цикл доработки останавливается на ≥ 60% покрытия ключевых слов (выше ~70% не добирать —
  по данным Huntr лучше всего работают CV с совпадением 40–60%) плюс хорошей оценке «рекрутера».
- **Верхняя треть CV** (до Experience) показывает главную задачу роли и ≥ 3 обязательных ключа — `check_cv.py` → `top_third`.
- **ATS-формат CV:** одна колонка, стандартные заголовки (Experience, Education, Skills),
  без таблиц, иконок и текста в картинках, формат .docx.
- **Структура CV:** one-pager, структура как в `Master_CV.pdf`
  (Career Profile → Career Highlights → опыт по компаниям → Founder Experience → Education → Languages).
- **Мастер-CV меняется не более чем на 30%** (с 2026-10-16, было 20%): адаптация — правки
  `knowledge-base/base-cv.md` (шапка, 2–3 фразы профиля, 1–2 highlight, 3–6 буллетов, Skills), а не
  переписывание. Проверяет `scorer/check_diff.py`. Если под роль нужно больше — это сигнал, что базовое
  CV не подходит под тип роли, решение за мной.
- **Шапка CV — точное название роли из вакансии** первым (без «(all genders)»), дальше позиционирование.
  Должности в опыте не меняются. Проверяет `check_diff.py --title` (`tagline_ok`).
- **Входы:** если ссылку на вакансию не удалось открыть (LinkedIn и др. требуют логина) —
  просить вставить текст в .md.

## Технические заметки
- **Модель агента по задачам** — экран «Агент» → «Модель по задачам» (`web/data/agent-models.json`, `web/agent.js` → `--model`).
  По умолчанию Sonnet; Haiku — быстрый фит, поиск фактов в надиктовках и база компаний. Без настройки CLI берёт Opus (≈ вдвое дороже).
- **Быстрый фит** (2026-10-27, задача `fitquick`, Haiku): вакансия с текстом оценивается одним ходом без инструментов —
  сервер сам кладёт в промпт разделы 2/4/5 брифа, профиль и реестр карточек (`prompts.fitQuick`, `runJob({ system })` →
  `claude -p --tools "" --system-prompt …` из временной папки), потом `score_job.py add` и черновые `01-keywords.json`
  / `01-requirements.md` с `"source": "quick"` (tailor-cv переделывает шаг 1). ≈ $0.004 и ~30 с против ≈ $0.33 у агента;
  на 22 вакансиях средняя разница балла 0.6–0.8, решение «7+ / ниже» совпало в 20–21. Подробный фит агентом —
  кнопка «Подробно (≈ $0.3)» (`POST /fit {mode:'deep'}`); ссылка без текста — тоже агентом (нужен WebFetch).
  Модель каждого запуска пишется в журнал (`runs.jsonl` → `model`).
- **Проверка всего приложения:** `.venv/bin/python tests/smoke.py` (сервер должен быть запущен; `--base` для другого
  порта, `--quick` без калибровок и писем) — статика, калибровки, все API на чтение, скачивание CV / писем / Master
  с проверкой имён файлов. Агента не запускает. Интерфейс (консоль, телефон) — проверять в браузере отдельно.
- Python: `.venv/` в корне (python-docx, pypdf). Вызывать `.venv/bin/python`.
- Node: `node_modules/docx` (docx-js 9.x) для рендера CV. `package.json` в корне.
- LibreOffice установлен через Homebrew (`soffice` в PATH). `check_cv.py` рендерит .docx → PDF и
  требует ровно 1 страницу с запасом ≥ 12 мм снизу. Визуальный превью: `soffice --headless
  --convert-to png`. Шрифт CV — Arial (есть в Word, macOS, Google Docs; Calibri на Mac нет).
- pandoc/poppler не установлены; PDF читать через `pypdf`.
- Для чтения PDF использовать `pypdf` из venv (так извлечён `knowledge-base/master-cv.md`).
